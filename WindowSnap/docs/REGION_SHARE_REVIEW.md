# WindowSnap region-share review

Line numbers refer to the reviewed working tree on 2026-10-16.

| Location | Severity | Status | Finding and resolution |
|---|---|---|---|
| `WindowSnap/Core/RegionFrameHub.swift:115` | High | Fixed | Every captured frame was appended to an unbounded serial queue and serialized into a full-frame `Data` object plus an atomic BGRA file. The sink is now nonblocking, retains only the newest pending frame, rejects older presentation timestamps, and publishes a sequence-numbered IOSurface-backed pooled buffer. |
| `WindowSnapVirtualCameraExtension/WindowSnapVirtualCameraProvider.swift:251` | High | Fixed | The extension read the full BGRA file every tick, allocated a new pixel buffer, and scaled it with a per-pixel Swift loop. It now looks up the IOSurface, caches frames by sequence/output size, uses pixel-buffer pools, and performs aspect-fit conversion with Core Image. |
| `WindowSnapVirtualCameraExtension/WindowSnapVirtualCameraProvider.swift:257` | High | Fixed | Sequence values restarted when the host relaunched while the extension retained its prior cache. Metadata now includes a per-host-session UUID; the extension clears its sequence and rendered-output caches whenever that epoch changes. |
| `WindowSnapVirtualCameraExtension/WindowSnapVirtualCameraProvider.swift:110` | Medium | Fixed | CMIO property, start, and stop callbacks could race on `activeFormatIndex` and the dispatch timer. Those transitions are now lock-protected and duplicate starts/stops are harmless. |
| `WindowSnap/Core/RegionShareController.swift:208` | High | Fixed outside engine | Replacing or stopping a camera capture could leave an in-flight engine callback able to republish an active frame after the inactive placeholder. Controllers now detach the old engine's frame sink before requesting stop, in addition to their existing generation checks. |
| `WindowSnap/Core/VirtualCameraExtensionManager.swift:61` | Medium | Fixed | Repeated enable actions submitted duplicate system-extension activation requests. Activations are now ignored while activation is pending or already enabled. |
| `scripts/build-virtual-camera-extension.sh:6` | High | Fixed | The generated product directory did not match the bundle-ID-based path searched by `VirtualCameraExtensionManager`, and signing did not materialize team-prefixed identifiers. One environment value now drives the ID/product path, signed builds require `TEAM_ID`, and extension/host plists and entitlements receive matching app-group and mach-service values. |
| `scripts/build-universal-bundle.sh:178` / `scripts/sign-nested-components.sh:29` | High | Fixed | The final nested signing pass replaced the generated team-prefixed extension app group with the source entitlement. Signed bundle and notarization paths now pass the generated host and extension entitlement files through every signing pass; source extension entitlements are only a development fallback. |
| `WindowSnap/UI/RegionSelectionOverlayWindow.swift:92` | High | Fixed | One keyboard monitor exists per display; without key-window filtering, Return or arrow input could operate on the first-created display instead of the active display. Confirm/nudge/resize commands now run only in the key overlay; Escape still cancels the whole selection. |
| `WindowSnap/UI/RegionSelectionOverlayWindow.swift:201` | Medium | Fixed | Region selection lacked VoiceOver semantics and an editable keyboard workflow. It now exposes a group label/help and confirm/cancel custom actions, announces size changes, keeps a completed drag editable, supports Return/Escape and 1-point/Shift-10-point movement with Option-resize, and uses semantic colors. |
| `WindowSnap/UI/ThrowOverlayWindow.swift:23` | Medium | Fixed | Throw choices were visual-only for VoiceOver and lacked arrow/Return navigation. The overlay and each position now expose roles, labels, help, and actions; the first choice is highlighted, arrows cycle, Return confirms, and Escape cancels. |
| `WindowSnap/UI/ThrowOverlayWindow.swift:133` | Low | Fixed | Redisplaying positions in the same overlay removed only tracked position views and leaked the old current-window highlight. Clearing now removes all prior overlay subviews. |
| `WindowSnap/Core/CaptureSessionStateMachine.swift:4` | High | Added, not wired by constraint | Added an actor with idle/starting/running/stopping transitions, generation tickets, stale completion rejection, duplicate suppression, and stop-during-start cancellation. Tests cover overlap behavior. Wiring it into capture ownership was intentionally omitted because `RegionCaptureEngine.swift` is off limits. |
| `WindowSnap/Core/RegionCaptureEngine.swift:194` | High | Not fixed — requires off-limits file | Each frame always creates both a `CGImage` and a separate pixel buffer, even when camera sharing has no image delegate. It also allocates rather than pools the output pixel buffer at `RegionCaptureEngine.swift:244`. The engine should conditionally render only requested outputs and own a size-keyed IOSurface pixel-buffer pool. |
| `WindowSnap/Core/RegionCaptureEngine.swift:100` | Medium | Not fixed — requires off-limits file | A stop requested while `startCapture()` is awaiting can make start return normally without clearing `isStoppingRequested`; `stopCapture()` also returns early when no running stream exists. Current controller generation guards prevent stale UI state, but the engine itself should use the new state machine or reset cancellation state on every aborted start. |
| `WindowSnap/Core/RegionFrameHub.swift:246` | Medium | Fixed | Publishing a new frame could release the surface named by metadata before the extension looked it up. The hub now retains the four most recently published pixel buffers, while the extension validates surface dimensions, pixel format, and sequence after lookup. Global IOSurface IDs remain the transport for compatibility. |
| `WindowSnap/Utils/WorkspaceCoordinateMath.swift:63` | Medium | Fixed | Legacy migration trusted unstable screen ordering. Entries without stable display identifiers now match the display containing the saved frame center, then the largest intersection, and use the saved index only as a fallback. If no match is available, the arrangement remains version 1 and is not persisted as normalized data. |
| `WindowSnap/UI/RegionMirrorWindow.swift:265` | Low | Partially fixed | The window is now main-actor isolated. Its capture delegate conformance uses `@preconcurrency` because the off-limits delegate protocol is nonisolated, though the engine currently dispatches callbacks to the main queue. The protocol should eventually declare main-actor delivery explicitly. |
| `Package.swift:4` / `WindowSnap/Core/VirtualDisplayAdapter.swift:1` | High | Fixed | Private `CGVirtualDisplay` declarations were always linked into the app target. `WINDOWSNAP_APP_STORE=1` now removes that dependency, defines `APP_STORE`, and compiles an unavailable stub; normal developer builds retain the feature. |
